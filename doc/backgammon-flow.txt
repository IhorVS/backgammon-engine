BACKGAMMON ENGINE FLOW
======================

The engine processes one command and returns a new state. The session owns the
current state, history, input and dice generation. The engine never waits for input.

COORDINATES AND COMMANDS
-----------------------
Board snapshots use physical indices 0..23.
Commands use active-side route points 1..24, increasing towards bearing off.
The virtual exact bearing-off destination is 25; it is not a physical board cell.

DiceRolled(color, first, second): externally generated values 1..6.
Move(color, from, diceValue): move from 'from' to 'from + diceValue'.
BearOff(color, from, diceValue): remove a checker using the selected value.
Enter(color, to): enter from the bar; getDiceValue() returns 'to'.
Abort(): colorless system cancellation.

PHASES
------
AWAITING_DICE: DiceRolled or Abort.
AWAITING_MOVE: variant-supported movement commands or Abort.
FINISHED: reject every command.
ABORTED: reject every command, including another Abort.

START
-----
The session supplies GameSetup(startingColor).
The engine creates the variant's initial arrangement with fifteen checkers per side.
It returns AWAITING_DICE, empty dice pools and option maps, and no winner.
Long backgammon also initializes headMoves and firstTurns.

ROLL
----
Validate phase, player color and both values.
Store the two-value roll; expand a double into four movement values.
Resolve legal first actions, including maximum dice usage and the higher-value rule.
If any action is available, return AWAITING_MOVE with the resolved option maps.
Otherwise, complete the turn and return AWAITING_DICE for the opposite side.

ACTION
------
Validate phase, color, parameters and resolved action availability.
Short backgammon also explicitly validates source, bar, destination and home conditions.
Apply the action on an independent board; move a hit checker to its bar if applicable.
Consume one occurrence of the selected movement value.

If the fifteenth checker was borne off:
  - set FINISHED and winner;
  - clear all available action maps;
  - preserve the active side, original roll and any unused movement values;
  - return without resolving another action or switching sides.

Otherwise, resolve actions for the updated position and remaining movement values.
Return AWAITING_MOVE for the same side if actions remain and the pool is not empty.
If the pool is exhausted or no action remains, complete the turn.

TURN COMPLETION
---------------
Switch the active side; return AWAITING_DICE.
Clear the original roll, remaining values and available action maps.
In long backgammon, reset headMoves and clear the outgoing side's first-turn flag.
Unusable movement values are discarded. There is no explicit pass command.

SYSTEM ABORT
------------
After rejecting terminal phases, Abort bypasses player color validation.
The default handler changes only gamePhase to ABORTED using toBuilder().
Board, active side, dice, action maps and variant-specific fields are preserved.
No winner is declared. Session policy determines when to submit Abort.

ERRORS AND OWNERSHIP
--------------------
Rejected commands throw EngineCommandException and return no new state.
Technical failures follow the shared AbstractGameEngine contract.
Supplied state containers store references without copying or validating them;
creating code must supply consistent immutable snapshots and collections.
Available action maps belong to the supplied snapshot; do not edit them manually.

TRANSITION EVENTS
-----------------
The initial state contains GameStarted(startingColor).
Each resulting state contains only the ordered events produced by the call
that created it; the event list is replaced by every successful command.
A checker hit precedes the active checker's move or entry. A turn change follows
the action events when the turn ends. Bearing off the final checker is followed
by GameFinished(winner), without a turn change. Abort produces GameAborted.
Checker route points in events use active-side-relative points, as commands do.
Keeping successive states also preserves the event sequence for the session.

BOUNDARIES
----------
Starting side selection and opening-roll orchestration belong to the session.
The engine accepts any two valid values in AWAITING_DICE, including opening doubles.
The engine records a winner, not gammon/backgammon scores or doubling-cube stakes.
Event publication, persistence, networking or automatic deadlock adjudication is not implemented.
